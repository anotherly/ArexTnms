## 2. 주요 변경

- `vw_tnms_gateway_device_live`: PING 상태를 `1=성공`, `-1=실패`, `0=미확인`으로 판정. 최근 수집 허용시간(기본 5분) 초과 시 `UNKNOWN`; 최근 실패 상태는 `OFFLINE`. 과거 실패값을 현재 실패로 오인하지 않음.
- 설비 목록·집계: 최근 PING 실패 건수와 미확인 건수 분리, 최근 5분 성능값 여부 `USAGE_FRESH_YN` 반환, 현재값 평균은 최근 수집 건만 반영.
- 전송: 기존의 근거 없는 '전송 성공률/평균 처리시간' 숫자를 없애고 PING 및 최근 수집 장비 현황으로 대체. 실제 장비간 링크가 없으므로 앞의 5대 목록을 구성도처럼 연결하지 않음.
- 행선: 기본 탭 '전체 장비'로 열어 미분류 장비도 보이게 함. '분류 미확정' 탭 추가. HSE/LSE의 '연결' 표시를 실제 연결 검증이라고 주장하지 않음. 장애 메시지는 `raw_event_action`에서 수신된 발생 중 장애만 표시.
- 보고서: `web_dsblty_info` 시연용 장애 대신 `raw_event_log` 장애 발생(`event_yn=1`, 등급 1~5) 사용. 보고서 날짜는 `event_dt`(장애 실제 발생시각)를 기준으로 함. `reg_dt`와 다르므로 과거 발생시각의 HISTORY 데이터는 11/04 날짜로 집계하지 않음. 장비 미매핑 장애는 `역사 미매핑`으로 보존해서 조회.
- RAW 조회: 성능은 `raw_usage_log`; 수신 메시지는 EMS가 식별 가능한 `raw_receive_log` 사용. EMS ID 없는 설정/시작/종료 프레임은 시스템 권한을 특정할 수 없어서 제외함. 예전 웹용 `web_link_raw_data`는 사용하지 않음.
- 성능 화면: CPU/MEMORY 상태는 '수집 중' 또는 '미확인·수집지연'으로 표시. 실제 임계치 장애 판정과 구분. TOP5는 최근 5분 수신 장비만 표시. 과거 수집값은 장비 목록에 시간과 함께 남아 있을 수 있음.
- 데이터 권한: 5개 EMS 필터는 Java 서버 권한 `SystemDataScope`에서 생성해 SQL에 전달. UI 파라미터는 권한을 확대할 수 없음.
